# Stage 09 斜杠命令注册与分发 Checklist

> 每一项都通过运行代码或观察行为验证。验收时记录实际结果和证据，不以“应该可以”代替执行。

## 验证命令

- Stage 09 自动化场景：`python -m pytest -q -k slash`
- 当前工作区全量回归：`python -m pytest -q`
- Python 语法编译：`python -m compileall -q src`
- 空白与补丁检查：`git diff --check`

## 注册与启动

- [ ] **AC1：完整命令元数据可用。** 十个公开命令均具有名称、固定别名、描述、用法、类型和处理行为，可选参数提示与隐藏标记符合规格。（验证：运行 Stage 09 自动化场景，观察默认命令目录和帮助输出中的十条元数据完整且顺序固定。）
- [ ] **AC1：主名称冲突在启动前失败。** 两条命令使用相同名称或大小写变体时，应用拒绝进入输入循环并指出冲突标识及双方命令。（验证：运行 Stage 09 自动化场景中的重复名称和大小写冲突启动用例，观察退出码为 `1` 且 TUI 未启动。）
- [ ] **AC1：别名冲突在启动前失败。** 同命令重复别名、跨命令重复别名、别名占用其他主名称以及隐藏命令撞名都被拒绝。（验证：运行 Stage 09 自动化场景中的全部别名冲突用例，观察每个用例均在注册阶段失败。）
- [ ] **AC1/AC18：冲突不会留下部分命令集。** 注册失败后不能继续查找或执行已经遍历过的命令。（验证：运行原子注册失败场景，观察没有创建可交互的注册中心或 TUI。）

## 解析与分流

- [ ] **AC2：空输入早返回。** 空字符串、空格、Tab 和换行均不显示错误、不调用命令、不发送 Agent 请求。（验证：运行 Stage 09 自动化场景，观察四类输入的命令调用数和 Agent 调用数均为零。）
- [ ] **AC2：命令大小写不敏感。** `/HeLp` 及别名的大小写变体都命中对应主命令。（验证：运行 Stage 09 自动化场景，观察大小写变体与小写主命令得到相同行为。）
- [ ] **AC2：参数只切分一次。** 命令名在第一个空白处分界，参数内部空白保持不变，整体首尾空白被忽略。（验证：运行包含空格、多个空格和 Tab 分隔的自动化场景，观察处理行为收到的参数正文符合输入。）
- [ ] **AC2/AC21：普通文本进入原有对话。** 不以 `/` 开头的输入只发送一次 Agent 请求，并继续输出标准 Agent 事件流。（验证：运行 Stage 09 自动化场景中的普通问题，观察 fake Agent 只记录一条规范化用户消息。）
- [ ] **AC3/AC17：本地与界面命令绕过 Agent。** 除 `/compact` 的既有摘要路径外，本地和界面命令不形成普通用户消息或 Agent 请求。（验证：连续执行所有本地和界面命令，观察 Agent 普通请求计数保持为零。）
- [ ] **AC3：未知命令不会降级为对话。** 输入 `/missing value` 时显示原命令和 `/help` 引导，不进入会话历史。（验证：运行未知命令场景，观察返回输入循环且 Agent 与会话记录计数不变。）
- [ ] **AC4：命令不依赖终端框架。** 使用不导入或初始化现有终端渲染组件的 fake 控制实现，可以执行全部命令处理行为。（验证：运行 Stage 09 自动化场景中的纯 fake controller 用例，观察全部 handler 可调用。）
- [ ] **AC18：单条命令异常被隔离。** 处理行为抛出异常时用户看到稳定命令错误，随后输入的正常命令仍可执行。（验证：运行“失败命令后执行帮助”场景，观察两次输入均返回且第二条帮助正常显示。）

## 内置命令

- [ ] **AC5：`/help` 列表完整且确定。** 列表只展示十个公开命令，并按 `help, compact, clear, plan, do, session, memory, permission, status, review` 排列。（验证：运行 `/help` 场景，逐项比对名称、描述和用法及其顺序。）
- [ ] **AC5：帮助详情支持主名称和别名。** `/help status` 与 `/help stat` 都展示 `/status` 的主名称、别名、描述、用法、类型和参数提示。（验证：运行两个详情场景，观察输出内容一致。）
- [ ] **AC5/AC16：隐藏退出不能通过帮助发现。** `/help`、`/help exit` 和 `/help quit` 均不展示隐藏命令详情。（验证：运行三种帮助场景，观察输出中不存在 `/exit` 或 `/quit` 元数据。）
- [ ] **AC6：`/compact` 只触发一次手动压缩。** 无参数时完整显示成功、无需压缩、应急、熔断或失败状态，不发送普通用户消息；有参数时只显示用法。（验证：运行各压缩报告 fixture 和非法参数场景，观察压缩调用计数分别为 1 和 0。）
- [ ] **AC7：`/clear` 完整复位会话。** 有历史、PLAN 模式和会话级权限时，执行后历史为空、模式为 DEFAULT、会话权限复位且产生新会话状态。（验证：运行清空集成场景，观察四项状态均变化且模型请求数为零。）
- [ ] **AC8：`/plan` 进入现有计划模式。** 执行后写工具沿用计划模式审批，模式标记为 `[PLAN]`；重复执行只显示幂等状态消息。（验证：运行计划模式和重复进入场景，观察状态及审批行为。）
- [ ] **AC8：`/do` 返回默认模式。** 执行后模式标记为 `[DEFAULT]`，写工具回到默认权限行为；重复执行保持幂等。（验证：运行退出计划模式和重复退出场景，观察状态及审批行为。）
- [ ] **AC9：`/session` 只显示当前会话。** 输出包含当前写入 ID、内存消息数、new/restored 来源、可选恢复 ID和最近时间，不列出其他会话。（验证：分别运行新会话和恢复会话场景，观察字段及其他会话 ID 不出现。）
- [ ] **AC10：`/memory` 显示双作用域摘要。** 输出包含用户级和项目级路径、笔记数、索引行数、字节数及最近诊断代码。（验证：运行具有两类记忆 fixture 的场景，逐项核对摘要值。）
- [ ] **AC10/AC19：`/memory` 不显示正文。** 笔记和索引中放置唯一敏感标记后，命令输出中不存在该标记。（验证：运行敏感正文 fixture，搜索捕获输出无匹配。）
- [ ] **AC11：`/permission` 查询档位与来源。** 无参数时能区分 strict/default/permissive 以及会话、本地项目、仓库项目、用户全局或默认来源。（验证：运行各权限快照场景，观察中文档位和来源正确。）
- [ ] **AC11：`/permission` 只接受三种设置值。** 三种合法参数及大小写变体能设置会话档位；非法、缺失必要值和多余参数只显示用法。（验证：运行参数化场景，观察合法设置生效、非法设置调用数为零。）
- [ ] **AC12：`/status` 展示全部约定状态。** 输出按固定顺序包含工作区、模式、权限、Token、会话、记忆、Git 和 MCP。（验证：运行完整状态 fixture，逐段核对字段和值及顺序。）
- [ ] **AC12：Git 状态字段正确。** 仓库根、分支、上游、ahead/behind、staged、unstaged 和 untracked 数量与临时仓库一致，ignored 文件不计入。（验证：运行临时 Git 仓库场景并与 `git status --porcelain=v2 --branch` 结果比对。）
- [ ] **AC12：非 Git 和单项失败可降级。** 非仓库显示不适用；任一 Token、会话、记忆、Git 或 MCP 状态源失败时，该项显示未知，其他项仍完整。（验证：运行非仓库及逐项抛错场景，观察命令均正常返回。）
- [ ] **AC12/AC17：MCP 状态不主动探测。** `/status` 只读取当前服务状态、工具数和诊断类别，不调用初始化、可用性确保、重连或网络请求。（验证：fake pool 将主动方法设为失败，运行状态场景仍通过且主动方法调用数为零。）
- [ ] **AC13：`/review` 展开固定提示词。** Agent 收到的消息覆盖 staged、unstaged、untracked、ignored、缺陷、回归、安全和测试缺口语义，且不是 `/review` 字面量。（验证：运行审查命令场景，逐项检查 fake Agent 收到的唯一用户消息。）
- [ ] **AC13：审查提示词进入会话历史。** `/review` 产生的展开提示词作为普通用户消息持久化，后续对话可以引用该轮。（验证：运行审查后继续提问场景，观察存档和后续请求历史都包含展开提示词。）
- [ ] **AC14：所有固定别名与主命令等价。** `h, ?, comp, cls, p, d, sess, mem, perm, stat, rev` 及其大小写变体分别执行对应主命令。（验证：运行别名参数化场景，观察每组调用目标和结果一致。）
- [ ] **AC14/AC16：`/exit` 与 `/quit` 均可退出。** 两个隐藏入口无参数时正常结束 TUI，有参数时显示用法而不退出。（验证：分别运行两个退出入口及非法参数场景，观察分发结果。）
- [ ] **AC17：相同状态产生相同输出。** 对相同命令目录和状态快照重复执行帮助、补全和状态命令，输出文本及顺序完全相同。（验证：运行重复执行场景，逐字节比较两次结果。）

## 补全与终端

- [ ] **AC8/AC18：增强终端模式栏动态更新。** 初始显示 `[DEFAULT]`，执行 `/plan` 后显示 `[PLAN]`，执行 `/do` 或 `/clear` 后恢复 `[DEFAULT]`。（验证：运行动态 toolbar callable 场景，依次观察三个状态值。）
- [ ] **AC20：普通输入降级仍可用。** 模拟增强终端不可用后，提示符包含当前模式标记，普通消息和斜杠命令都能继续执行。（验证：运行无控制台缓冲区场景，观察输入、命令和退出流程完成。）

## 状态与安全

- [ ] **AC12/AC17：Token 状态完整且无副作用。** 显示当前估算值、窗口上限、占用比例和估算来源；查询不压缩、不刷新长期记忆、不改变 usage 锚点、不调用模型。（验证：运行 Token 前后状态对比场景，观察四字段正确且所有副作用计数为零。）
- [ ] **AC9：会话来源遵守首次请求边界。** 启动后直接 `/session` 显示 new；第一次普通消息或 `/review` 完成恢复后显示 restored 和旧会话 ID。（验证：运行恢复前后两次查询场景，观察来源按顺序变化且查询本身不触发恢复。）
- [ ] **AC12：Git 双状态文件分别计数。** 同一文件同时 staged 和 unstaged 时两个计数各增加一次，重命名和冲突记录也按 XY 状态稳定统计。（验证：运行临时仓库及 porcelain fixture 场景，观察计数符合记录。）
- [ ] **AC18：综合状态逐项故障隔离。** 同时让两个状态源失败时，两项显示稳定错误类别，其他六项仍有值，输入循环保持可用。（验证：运行双故障后继续 `/help` 的场景，观察状态输出与后续帮助均成功。）
- [ ] **AC19：输出不泄露敏感内容。** 状态、会话、记忆和异常输出不包含 API key、MCP header/env、笔记正文、未授权文件正文或异常原始 secret。（验证：在所有 fixture 注入唯一敏感标记，运行 Stage 09 自动化场景并搜索捕获输出无匹配。）
