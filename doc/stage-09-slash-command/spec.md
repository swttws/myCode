# Stage 09 斜杠命令注册与分发 Spec

## 背景

myCode 当前已具备会话、上下文压缩、计划模式、权限系统、长期记忆和 MCP 工具能力，但斜杠命令仍以条件分支直接写在终端输入循环中。命令元数据、解析、执行和界面输出没有统一边界，继续增加帮助、状态查询、补全和提示词命令会扩大界面层职责，也难以统一检测别名冲突。

本阶段建立统一的斜杠命令机制。斜杠输入不进入普通对话分支；本地操作和界面状态变更绕过 Agent，预设提示词命令则展开为普通用户消息后进入 Agent。由此保证常用操作响应快、行为确定，并避免无意义的模型调用。

## 目标

- 集中管理命令名称、别名、描述、用法、类型、参数提示、隐藏状态和处理行为。
- 启动时验证所有命令名称与别名，任何重复或交叉占用都导致启动失败。
- 统一解析斜杠输入，支持大小写不敏感的命令匹配、原样参数传递、空输入忽略和未知命令引导。
- 区分本地操作、界面状态操作和预设提示词三类执行行为。
- 通过稳定的界面控制边界执行命令，使命令逻辑不依赖具体终端渲染框架。
- 在用户提交输入时先执行命令分流，只有普通输入和展开后的提示词命令进入 Agent。
- 支持主名称和别名的 Tab 补全；单一候选直接补全，多个候选展示选择菜单。
- 提供十个公开内置命令，并以隐藏方式保留 `/exit` 兼容行为。
- 让 `[DEFAULT]` 与 `[PLAN]` 模式标记随计划模式实时联动。
- 保持现有清空、压缩、权限、Agent 事件流和长期记忆语义兼容。

## 功能需求

- **F1：命令登记**  
  每条命令必须登记名称、零个或多个别名、简短描述、用法示例、命令类型和处理行为，并可选登记参数提示与隐藏状态。命令类型固定为本地操作、界面状态操作、预设提示词三类。

- **F2：启动期唯一性校验**  
  启动时必须按大小写不敏感规则校验所有主名称和别名。主名称重复、别名重复、别名占用其他主名称，或隐藏命令与公开命令撞名，都必须立即终止启动并指出冲突名称。

- **F3：统一输入解析**  
  空输入或纯空白输入直接忽略。去除输入首尾空白后，仅当第一个字符为 `/` 时才解析命令；命令名在首个空白处分界并转为小写，剩余内容作为参数传给处理行为。普通输入保持现有对话流程。

- **F4：命令分流**  
  用户提交输入后必须先经过命令分流。已识别的本地操作和界面状态操作不得发送给 Agent；预设提示词命令展开后作为普通用户消息进入 Agent 和会话历史。未知斜杠命令不得降级成普通对话。

- **F5：未知命令与异常处理**  
  未知命令必须显示原命令名并引导用户输入 `/help`。处理行为运行失败时显示明确错误并返回输入循环，不发送兜底模型请求，也不终止应用。

- **F6：界面控制边界**  
  命令只能通过统一控制能力显示消息、发送用户消息、查询或切换会话模式、查询 Token 状态以及刷新综合状态，不直接依赖具体终端组件。

- **F7：帮助命令**  
  `/help` 列出全部公开命令的名称、简短描述和用法；`/help <命令或别名>` 显示该命令的名称、别名、描述、用法、类型和参数提示。隐藏命令不出现在列表或详情查询结果中。

- **F8：压缩命令**  
  `/compact` 直接触发现有手动上下文压缩流程，不作为普通用户消息发送。压缩结果继续显示成功、无需压缩、应急压缩、熔断或失败状态；额外参数显示用法。

- **F9：清空命令**  
  `/clear` 清空当前会话上下文，并继续复位计划模式和会话级权限档位；不得发送模型请求。额外参数显示用法。

- **F10：计划模式命令**  
  `/plan` 开启现有计划模式，`/do` 退出计划模式。两者只改变会话状态和写工具审批策略，不自动请求 AI；重复切换到当前模式时返回确定的状态消息。

- **F11：会话命令**  
  `/session` 显示当前会话 ID、消息数、新建或恢复来源以及最近更新时间，不提供会话列表、切换或指定恢复能力。

- **F12：记忆命令**  
  `/memory` 显示用户级和项目级记忆路径、笔记数量、索引大小及最近诊断，不展示笔记或索引正文。

- **F13：权限命令**  
  `/permission` 无参数时显示当前有效权限档位和来源；参数只接受 `strict`、`default`、`permissive`，并修改会话级档位。非法或多余参数显示用法，不发送模型请求。

- **F14：综合状态命令**  
  `/status` 显示当前模式、权限档位、当前上下文估算 Token、模型窗口上限、占用比例、估算来源、会话摘要、记忆摘要和工作区路径。

  Git 状态包含仓库根目录、当前分支、上游领先/落后数量，以及 staged、unstaged、untracked 文件计数；非 Git 目录明确标注。

  MCP 状态只读取连接池当前状态和最近诊断，不主动联网、探测或重连。无法取得某项状态时标记为未知，其余部分仍正常显示。

- **F15：审查命令**  
  `/review` 展开为固定提示词，要求 AI 审查当前工作区全部未提交改动，包括已暂存、未暂存和未跟踪文件，但忽略 Git 已忽略文件；优先报告缺陷、行为回归、安全风险和测试缺口。展开后的提示词作为普通用户消息进入 Agent 和持久会话历史。

- **F16：固定别名**  
  公开命令使用以下别名：`help=h,?`、`compact=comp`、`clear=cls`、`plan=p`、`do=d`、`session=sess`、`memory=mem`、`permission=perm`、`status=stat`、`review=rev`。别名与主名称具有相同解析和执行语义。

- **F17：Tab 补全**  
  输入斜杠命令时，按大小写不敏感的前缀匹配公开命令主名称和别名。单一候选直接补全；多个候选显示可选择菜单。补全只作用于命令部分，不生成参数候选；隐藏命令及其别名不参与。

- **F18：模式状态栏**  
  增强终端底部状态栏持续显示 `[DEFAULT]` 或 `[PLAN]`，并在模式变化后刷新。无法使用增强终端时，模式标记显示在普通输入提示符中。

- **F19：退出兼容**  
  保留隐藏的 `/exit` 和别名 `/quit`，继续正常退出应用；二者不出现在帮助和 Tab 补全中。

## 非功能需求

- **N1：响应性能**  
  除 `/compact` 沿用现有压缩流程、`/review` 明确进入 Agent 外，其他命令不得调用模型。命令查找和分流不得扫描对话历史；`/status` 只执行本地 Git 查询并读取已有 MCP 状态。

- **N2：确定性**  
  在相同注册信息、会话状态和本地状态下，命令解析、别名解析、帮助排序、补全候选、状态字段和错误结果必须一致。公开命令展示采用固定顺序，不依赖无序容器遍历。

- **N3：兼容性**  
  普通用户输入、Agent 事件流、手动压缩、清空、计划模式、权限档位、长期记忆和退出行为必须保持现有语义。旧 `/plan-only` 命令不再作为公开入口，由 `/plan` 和 `/do` 取代。

- **N4：边界隔离**  
  命令登记、解析、分发和内置行为必须与具体终端渲染实现分离。更换界面实现时，不应重写命令定义或解析规则。

- **N5：启动可靠性**  
  注册表完成构建后、进入交互循环前必须完成冲突校验。存在冲突时不得以部分命令集继续运行。

- **N6：故障隔离**  
  单条命令失败不得破坏注册中心、会话模式或后续输入循环。综合状态中的单个数据源失败不得阻止其他状态项展示。

- **N7：安全性**  
  状态、会话和记忆命令不得输出 API key、完整记忆正文、未授权文件正文或敏感 MCP 配置。`/review` 仍受现有工具权限和审批策略约束，不能因来自内置提示词而绕过权限。

- **N8：终端兼容性**  
  增强终端提供补全菜单和底部状态栏；缺少控制台能力时必须降级为可输入、可执行命令的普通终端，不因状态栏或补全不可用而退出。

- **N9：可测试性**  
  注册冲突、解析、分发、每条内置命令、补全、模式标记和输入分流必须可在不访问真实模型或外部网络的情况下验证。Git 检查使用临时仓库，MCP 状态使用固定测试状态。

- **N10：可观测性**  
  用户必须能区分未知命令、参数错误、命令执行失败、状态未知和 Agent 返回错误。错误信息包含可行动的命令用法或 `/help` 引导，但不暴露内部敏感数据。

- **N11：代码质量**  
  命令相关实现集中在独立的斜杠命令边界中；命名准确、代码简洁。注册冲突、输入分流、提示词转发、模式刷新和故障隔离等关键路径保留说明原因的中文注释，显而易见的代码不添加叙述性注释。

- **N12：扩展边界**  
  后续增加命令时，应只需登记元数据和处理行为，不需要修改解析器或增加新的输入条件分支。

## 不做的事

- 不支持用户自定义命令、项目级命令配置或从文件发现命令。
- 不支持运行时动态注册、卸载或覆盖命令。
- 不支持由模型或当前上下文动态生成预设提示词。
- 不新增命令级权限策略；命令自身按固定类型分流，进入 Agent 后仍使用现有工具权限系统。
- 不为命令参数提供 Tab 候选、动态参数补全或模糊补全。
- 不提供 `/help` 模糊搜索。
- 不保留 `/plan-only` 作为公开或隐藏兼容命令；计划模式统一使用 `/plan` 和 `/do`。
- 不提供会话列表、会话切换、指定会话恢复或会话删除。
- 不展示、搜索、编辑或删除长期记忆正文。
- 不让 `/status` 主动探测、重连或修复 MCP 服务。
- 不在 `/status` 中列出完整 Git 变更文件清单。
- 不让 `/review` 接收文件、目录或 Git 范围参数。
- 不构建复杂全屏命令面板、命令历史浏览器或图形化命令管理界面。
- 不把未知斜杠输入降级为普通用户消息交给 AI。
- 不改变现有 Agent 工具权限、压缩算法、长期记忆存储格式或协议层语义。

## 验收标准

- **AC1（F1/F2）**：注册包含完整必填元数据的命令集可以启动；构造主名称重复、别名重复、大小写变体冲突、别名与主名称冲突时，应用均在进入输入循环前失败并指出冲突名称。
- **AC2（F3）**：空白输入不产生动作；`/HeLp` 能命中 `/help`；带参数输入只按第一个空白分隔命令与参数；不以 `/` 开头的输入进入普通对话。
- **AC3（F4/F5）**：本地及界面命令不会调用 Agent；未知斜杠命令显示原名称和 `/help` 引导，且不会进入对话历史。
- **AC4（F6）**：使用不导入或初始化现有终端渲染组件的测试控制实现，可以执行全部命令行为。
- **AC5（F7）**：`/help` 按固定顺序展示十个公开命令；`/help stat` 能通过别名展示 `/status` 详情；`exit` 和 `quit` 不出现在列表，也无法通过帮助查看。
- **AC6（F8）**：执行 `/compact` 时只触发一次现有手动压缩，完整显示压缩状态，不发送普通用户消息；带参数时显示用法。
- **AC7（F9）**：在存在对话历史、计划模式和会话级权限设置时执行 `/clear`，历史被清空，模式回到默认，权限会话设置被复位，且没有模型请求。
- **AC8（F10/F18）**：执行 `/plan` 后写工具采用现有计划模式审批行为，状态栏显示 `[PLAN]`；执行 `/do` 后恢复默认行为并显示 `[DEFAULT]`；重复执行得到稳定状态消息。
- **AC9（F11）**：`/session` 能显示当前会话 ID、消息数、来源和最近更新时间，不列出其他会话。
- **AC10（F12）**：`/memory` 同时显示用户级和项目级路径、笔记数量、索引大小与诊断摘要，输出中不存在笔记或索引正文。
- **AC11（F13）**：`/permission` 能查询档位与来源，并能设置三种合法会话档位；非法、缺失必要值或多余参数均显示用法且不调用模型。
- **AC12（F14）**：在有改动的 Git 仓库和已连接/异常 MCP 状态下，`/status` 展示全部约定字段；在非 Git 目录或某个状态源失败时，对应字段显示未知或不适用，其他字段仍正常展示；执行期间没有 MCP 网络探测。
- **AC13（F15）**：执行 `/review` 后，Agent 收到的是固定审查提示词而非字面量 `/review`；提示词明确覆盖 staged、unstaged、untracked 并忽略 ignored 文件，且作为普通用户消息写入会话历史。
- **AC14（F16）**：十组公开别名分别解析到对应主命令，大小写变体同样有效；`/quit` 与 `/exit` 均正常退出。
- **AC15（F17）**：输入唯一前缀并按 Tab 时直接补全；输入具有多个公开候选的前缀时出现选择菜单；参数位置、`/exit` 和 `/quit` 不产生候选。
- **AC16（F19）**：`/exit` 与 `/quit` 保持可用，但帮助列表、帮助详情和补全候选均不暴露它们。
- **AC17（N1/N2）**：除 `/compact` 和 `/review` 外，连续执行全部公开命令不会产生模型请求；相同状态下帮助、补全和状态输出顺序一致。
- **AC18（N5/N6/N10）**：任一命令处理行为抛出异常后，用户看到可区分的命令错误，下一条输入仍可执行；综合状态单项失败不会影响其他项。
- **AC19（N7）**：状态、会话、记忆和错误输出不包含 API key、记忆正文或敏感 MCP 配置；`/review` 发起的工具操作仍触发现有权限判断。
- **AC20（N8）**：模拟增强终端不可用后，应用使用带模式标记的普通提示符继续接收普通输入和斜杠命令。
- **AC21（端到端）**：用户依次执行 `/help`、`/plan`、`/status`、普通问题、`/do` 和 `/clear`；命令在本地正确执行，仅普通问题进入 Agent，模式标记和最终清空状态正确。
- **AC22（端到端审查）**：临时 Git 仓库同时包含 staged、unstaged、untracked 和 ignored 文件时执行 `/review`；Agent 按预设范围开展审查，产生正常回复并保留该轮会话记录。
