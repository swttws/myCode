# myCode Stage 10：Skill 系统规格说明

## 背景

myCode 已具备稳定提示词构建、工具注册、会话历史、上下文管理和斜杠命令能力，但可复用的 AI 操作仍需用户反复输入相同提示词。若启动时直接加载所有操作的完整指令，会持续占用上下文，也会让模型面对过多无关工具，降低工具选择准确率。

因此需要把可复用操作封装为独立 Skill：启动时只暴露名称和一句说明，实际使用时再加载完整 SOP，并在执行期间仅开放该 Skill 声明的工具。

## 目标

- 允许用户通过带 YAML 元信息的 Markdown 文件定义可复用 Skill。
- 支持项目、用户、内置三级来源，并按项目高于用户、高于内置的顺序覆盖。
- 启动时仅向 Agent 提供 Skill 名称和说明，需要时再按需加载完整指令。
- 完整指令激活后持续进入每轮环境上下文，并允许多个 Skill 同时激活。
- 支持共享当前对话和独立对话两种执行模式。
- 独立执行支持不携带上下文、最近 N 轮和即时生成上下文摘要三种策略。
- 每次执行严格采用当前 Skill 自己的工具白名单，系统加载工具始终可用。
- Skill 自动成为斜杠短命令，并在下一次使用前自动发现文件更新。
- 提供中文说明的 `commit`、`review`、`test` 内置样板。
- 保持实现简洁，只在关键路径、安全边界和不直观控制流处添加中文注释。

## 功能需求

### F1：Skill 定义格式

每个 Skill 由 YAML frontmatter 和非空 Markdown 正文组成。frontmatter 必须声明：

- 唯一名称
- 一句话说明
- 可见工具白名单
- 执行模式：共享或独立
- 独立模式的上下文策略及其参数
- 可选的指定模型

正文作为发给模型的 SOP 指令。独立上下文策略支持：

- 不携带主对话上下文
- 携带最近 N 个完整轮次
- 执行前生成主对话摘要

指定模型仅对独立模式生效；共享模式始终使用主对话模型。

### F2：参数替换

Skill 正文支持参数占位符。通过斜杠命令或加载工具传入的原始参数会替换对应占位符，不执行表达式或代码。未传入参数时使用空内容，不得残留未解析的参数标记。

### F3：统一目录型 Skill

每个 Skill 必须独占一个目录，入口文件固定为该目录下的 `SKILL.md`。最小 Skill 目录可以只包含入口文件；需要扩展时，可在同一目录内增加模板、示例、辅助脚本和参考文档。

加载 Skill 时，只返回入口 SOP 和资源清单。后续通过同一个系统加载工具按相对路径读取单个资源，不自动加载整个能力包，也不自动执行辅助脚本。

资源访问必须限制在当前 Skill 目录内；路径穿越、符号链接逃逸和目录外读取必须被拒绝。

### F4：三级发现与覆盖

系统从项目级、用户级和内置级三个来源发现 Skill，优先级固定为：

```text
项目级 > 用户级 > 内置级
```

同一来源中的名称不得重复。跨来源同名时，使用最高优先级的有效版本。

单个文件解析失败时记录诊断并跳过，然后继续尝试较低优先级的同名版本；不得阻断其他 Skill 加载。最终注册顺序必须确定且可重复。

### F5：启动校验

启动时必须对最终生效的 Skill 元信息执行完整校验。

任一工具白名单引用不存在的工具时，启动立即失败并指出 Skill 名称和无效工具。Skill 名称与固定系统斜杠命令冲突时同样启动失败。

普通 Markdown 语法或 frontmatter 解析失败仍按 F4 隔离处理，不升级为整体启动失败。

### F6：第一阶段加载

启动时 Agent 只能看到每个有效 Skill 的名称和一句说明，不得看到完整 SOP、资源正文或辅助脚本内容。

Skill 摘要以确定顺序进入框架上下文，使模型能够判断何时需要加载 Skill，同时避免无关指令长期占用上下文。

### F7：按需加载工具

系统提供一个内置 Skill 加载工具，支持：

- 按名称加载入口 SOP
- 传入 Skill 参数
- 查看目录型 Skill 的资源清单
- 按相对路径读取单个资源

该工具属于系统能力，始终对模型可用，不受任何 Skill 工具白名单限制。未知 Skill、未知资源和越界路径必须返回稳定、可理解的错误。

### F8：激活与持续注入

入口 SOP 加载成功后，该 Skill 立即成为已激活状态。

所有已激活 Skill 的完整指令必须：

- 位于每轮重建环境上下文中最醒目的固定区域
- 在同一轮的后续模型调用中持续存在
- 不写入普通用户对话历史
- 按确定顺序同时注入，支持多个 Skill 激活
- 在有效热更新后使用新版本内容重新构建

读取目录资源不会重复激活 Skill，也不会改变当前执行范围。

### F9：共享执行模式

共享模式直接使用主对话的当前历史和主模型执行。Skill 执行产生的助手回复、工具调用和工具结果都保留在主历史中。

执行期间只向模型暴露当前 Skill 白名单内的工具，以及不受限制的 Skill 加载工具。执行结束后恢复主对话原有工具集。其他已激活 Skill 不参与当前白名单计算。

### F10：独立执行模式

独立模式创建临时对话执行 Skill，不把独立对话的详细消息、工具调用或工具结果合并进主历史。

执行前根据 Skill 配置选择一种上下文来源：

- `none`：不携带主历史
- `recent`：携带最近 N 个完整轮次，不截断工具调用链
- `summary`：使用一次无工具的模型调用，对执行时的主对话生成新摘要

独立模式使用 Skill 指定模型；未指定时使用主模型。指定模型只替换主配置中的模型 ID，继续复用当前协议、服务地址和凭据。执行结束后，将完成状态、关键结果和必要错误整理为摘要，显示给用户并写回主历史。

### F11：工具白名单

每个 Skill 必须拥有自己的工具白名单，包括允许为空的列表。

执行某个 Skill 时，只采用该 Skill 的白名单，不与其他已激活 Skill 的白名单求并集或交集。空白名单表示除系统加载工具外不提供普通工具。

权限审批、读写分类、超时和既有安全策略继续作用于白名单内工具；白名单不能提升权限。

### F12：斜杠短命令

每个最终生效的 Skill 自动注册同名斜杠命令，并进入帮助列表和输入补全。

调用斜杠命令时：

- 命令参数传给 Skill 的参数占位符
- 根据 Skill 配置选择共享或独立执行
- 项目级或用户级同名覆盖会同步反映到该命令
- 固定系统命令不得被 Skill 覆盖

现有硬编码 `/review` 行为迁移为内置 `review` Skill，避免命令冲突。

### F13：使用前热更新

系统不启动后台监听，而是在 Skill 补全、斜杠执行和加载工具调用前检查文件变化。

下一次交互必须能够发现新增、修改和删除：

- 有效新版本立即替换旧版本
- 删除高优先级版本后回退到较低优先级版本
- 普通解析失败按 F4 跳过并回退
- 新版本引用不存在工具时拒绝更新、显示配置错误并保留最后一个有效版本
- 已激活 Skill 更新后，其固定上下文使用新内容

### F14：清空会话

清空主对话时，必须同时清除：

- 所有已激活 Skill
- 当前 Skill 执行范围
- 尚未回流的临时 Skill 状态

Skill 注册信息和磁盘文件不删除；下一轮仍可从第一阶段摘要重新发现和加载。

### F15：内置样板

系统内置 `commit`、`review`、`test` 三个可覆盖 Skill：

- `commit`：检查待提交变更和必要验证，形成清晰提交
- `review`：审查变更中的缺陷、风险和测试缺口
- `test`：选择并运行相关测试，汇总失败原因和结果

三个内置 Skill 的一句说明必须使用中文，正文遵循统一 Skill 格式，不通过硬编码执行旁路实现。

## 非功能需求

- **N1：架构边界。** Skill 发现、激活和执行保持为独立领域能力，通过明确接口接入现有 Prompt、工具、会话和斜杠系统，不把供应商协议细节引入 Skill 核心。
- **N2：代码简洁。** 实现应复用现有能力，保持职责单一、控制流直接，避免为未纳入本阶段的市场分发、版本管理或远程 Skill 提前建立抽象。
- **N3：中文注释。** 仅在优先级回退、白名单切换、路径安全、热更新保底和历史隔离等关键路径添加简洁中文注释；自解释代码不添加叙述性注释。
- **N4：确定性。** 相同文件、工具注册表和会话状态必须产生相同的 Skill 解析结果、覆盖结果、摘要顺序、激活顺序和工具顺序。
- **N5：安全边界。** YAML 使用安全解析；资源路径必须规范化并限制在能力包内；辅助脚本不得自动执行；工具白名单不能绕过现有权限、审批、超时或路径限制。
- **N6：有界加载。** Skill 正文、frontmatter、资源清单和单次资源读取都必须设置大小上限。超限文件只影响对应 Skill 或资源，不得造成无限内存占用。
- **N7：热更新开销。** 不使用后台监听。使用前检查应优先依据文件元数据识别变化，仅重新解析变化的候选文件，避免每次交互无条件读取全部正文。
- **N8：故障可观测。** 被跳过文件、优先级回退、热更新拒绝和独立执行失败必须产生可定位诊断，同时避免输出凭据、完整历史或无关文件内容。
- **N9：兼容性。** 除 `/review` 迁移为内置 Skill、`/clear` 增加 Skill 状态清理外，既有对话、Prompt、工具、权限、压缩、会话恢复和固定斜杠命令行为保持不变。
- **N10：模型隔离。** 独立 Skill 的指定模型只替换主配置中的模型 ID，继续复用当前协议、服务地址和凭据；共享模式不得切换模型。
- **N11：测试隔离。** 自动化测试使用临时项目目录、临时用户目录、fake LLM 和固定输入，不读取真实用户 Skill，不调用真实网络或真实 API。
- **N12：文本兼容。** Skill 和资源以 UTF-8 读取；内置 Skill 的一句说明使用中文；用户正文和资源内容保持原样，不做隐式翻译。

## 不做的事

- 不做 Skill 市场、远程仓库、在线搜索、发布、安装或分享服务。
- 不做 Skill 版本号、依赖解析、升级策略、锁文件、签名或兼容性协商。
- 不提供图形化 Skill 编辑器、管理页面或安装向导。
- 不在启动时自动加载或激活完整 SOP。
- 不跨应用重启或 `/clear` 持久化已激活状态。
- 不引入后台文件监听线程或固定周期轮询。
- 不允许 Skill 自行声明供应商地址、协议或凭据，也不新增多模型档案管理。
- 不实现完整模板语言；参数替换不支持条件、循环、表达式或代码执行。
- 不自动执行 Skill 目录中的辅助脚本，也不自动安装脚本依赖。
- 不让工具白名单提升权限、跳过审批或覆盖系统级安全策略。
- 不实现白名单合并；每次执行只采用当前 Skill 自己的列表。
- 不把独立执行扩展为多 Agent 编排、递归委派或长期后台任务。
- 不保证兼容其他产品或第三方平台的 Skill 文件规范。
- 不改变现有上下文压缩、长期记忆和会话恢复算法。

## 验收标准

- **AC1（F1、F3）**：只包含 `SKILL.md` 的最小 Skill 目录和带有资源的 Skill 目录均可被发现；根目录下的散落 Markdown 不被识别。缺少必填元信息、正文为空、执行模式非法或上下文策略非法的入口被诊断并跳过。
- **AC2（F2）**：分别使用有参数和无参数调用 Skill，模型收到的 SOP 中占位符被原样参数或空内容替换，不执行其中的表达式或代码。
- **AC3（F3）**：加载 Skill 目录时只返回入口 SOP 和资源清单；再次调用同一系统工具可读取指定资源，而路径穿越、符号链接逃逸和不存在资源均被拒绝。
- **AC4（F4）**：项目、用户和内置层同时存在同名 Skill 时项目版本生效；删除项目版本后用户版本生效；项目版本解析失败时自动回退到用户版本并产生诊断。
- **AC5（F5）**：最终生效 Skill 的白名单包含未知工具时应用启动失败，并显示 Skill 名称和未知工具；与 `/clear` 等固定命令冲突时同样启动失败。
- **AC6（F6）**：捕获首次模型请求，只能观察到 Skill 名称和一句说明，不能搜索到 SOP 正文、示例、模板、脚本或参考文档中的标记文本。
- **AC7（F7）**：模型通过系统加载工具按名称获得完整 SOP 并激活 Skill；即使该工具未出现在 Skill 白名单中，后续仍可继续加载入口或资源。
- **AC8（F8）**：同时激活两个 Skill 后，当前轮及后续工具轮的每次模型请求都在固定高显著区域包含两份完整 SOP，顺序稳定，普通对话历史中不包含这些框架指令。
- **AC9（F9）**：共享 Skill 能读取主历史，使用主模型执行，并把回复、工具调用和工具结果保留在主历史；执行期间只暴露自身白名单，结束后恢复完整工具集。
- **AC10（F10）**：独立模式配置为不携带上下文时，临时对话请求中不出现主历史；完成后主历史只新增结果摘要，不包含独立对话的详细工具记录。
- **AC11（F10）**：独立模式配置最近 N 轮时，只携带最近 N 个完整用户轮次，并保留这些轮次内完整的工具调用与结果边界。
- **AC12（F10）**：独立模式配置摘要时，执行前发生一次不带工具的摘要模型调用；其输出进入独立对话上下文，不依赖已有压缩摘要。
- **AC13（F10、N10）**：独立 Skill 指定模型后，请求复用主配置的协议、地址和凭据，仅模型 ID 改变；共享 Skill 即使声明模型也仍使用主模型。
- **AC14（F11）**：两个白名单不同的 Skill 分别执行时，各自只能看到自己的工具列表；空白名单只保留系统加载工具，且既有权限拒绝和审批行为保持有效。
- **AC15（F12）**：新发现的 Skill 自动出现在帮助和补全中，并可通过同名斜杠命令执行；参数被正确传入；内置 `/review` 由 Skill 实现而非固定提示词旁路。
- **AC16（F13）**：无需重启应用，新增 Skill 在下一次补全或调用时出现，修改后的 SOP 在下一次调用时生效，删除高优先级版本后自动回退。
- **AC17（F13）**：热更新版本引用未知工具时，本次更新被拒绝并显示错误，随后执行仍使用最后一个有效版本；其他 Skill 不受影响。
- **AC18（F14）**：激活多个 Skill 后执行 `/clear`，下一次模型请求不再包含其完整 SOP，但仍包含可发现的名称和一句说明。
- **AC19（F15）**：默认安装可发现并执行 `commit`、`review`、`test`，三者说明均为中文；创建同名用户级或项目级 Skill 后按优先级覆盖。
- **AC20（N2、N3）**：代码检查确认新增模块职责集中，没有重复实现现有 Prompt、工具或斜杠能力；优先级回退、白名单切换、路径边界和热更新保底处具有简洁中文注释。
- **AC21（N4、N6、N7）**：相同输入重复加载得到一致顺序和内容；超限正文或资源被隔离拒绝；未变化文件在后续使用前检查中不重复解析正文。
- **AC22（N8、N9）**：单个 Skill 解析或资源读取失败不会影响普通聊天及其他 Skill；现有固定斜杠命令、权限、上下文压缩、会话恢复和工具执行回归测试通过。
- **AC23（N11、N12）**：全部自动化测试仅使用临时目录、fake LLM 和本地固定数据，在无网络、无真实 API key、无真实用户 Skill 的环境中通过；UTF-8 中文说明和正文保持原样。
