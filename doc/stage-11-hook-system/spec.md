# myCode Stage 11：Hook 系统规格说明

## 背景

myCode 已具备 Agent Loop、工具执行、权限拦截、提示词构建、上下文管理、项目记忆、Skill 和斜杠命令能力，但生命周期中的固定重复动作仍主要依赖人工盯守。例如工具执行前的细粒度安全拦截、轮次开始时补充上下文、工具完成后的格式化或通知，都需要用户或模型在每次对话中显式处理。

本阶段需要引入声明式 Hook 系统，把触发时刻明确、条件稳定、动作固定的重复工作交给 myCode 自动执行。Hook 不替代权限系统、Prompt 系统或 Skill 系统，而是在 Agent 生命周期关键节点上提供统一、可校验、可失败隔离的自动化扩展点。

## 目标

- 使用“事件 + 条件 + 动作”三要素声明 Hook 规则。
- 条件可省略，表示无条件触发；事件和动作必须声明。
- 生命周期事件覆盖会话级、轮次级、消息级、工具级，并包含少量系统级事件。
- 工具执行前 Hook 支持拦截，并把拒绝原因作为工具结果反馈给模型。
- 条件表达式复用权限规则的匹配语义，支持精确、反向、正则和 glob。
- 条件逻辑只支持“全部满足”或“任一满足”二选一，单条规则内不混用。
- 支持执行 shell 命令、注入提示词、发 HTTP 请求和启动子 Agent 四种动作。
- 支持只跑一次、后台异步和命令超时三种执行控制。
- 拦截类事件不允许后台异步执行。
- Hook 执行失败只记录日志，不中断 Agent 主流程。
- Hook 规则从 YAML 声明式加载，并在启动时集中校验。
- Hook 相关实现集中在 `hook` 包下，Agent、工具和 CLI 只通过明确入口接入。

## 功能需求

### F1：Hook YAML 格式

Hook 配置文件必须是版本化 YAML。每条规则必须包含：

- `event`：触发时刻。
- `if`：可选条件表达式。
- `action`：动作类型和该动作需要的字段。

规则可以包含可选 `id`，用于日志、诊断和测试断言。未声明 `id` 时，系统使用稳定位置生成可读标识。未知字段、非法事件、非法动作、非法条件结构和非法执行控制必须在加载阶段报错。

最小合法规则示例：

```yaml
version: 1
hooks:
  - event: turn_start
    action:
      type: prompt
      content: "本轮请优先检查测试影响。"
```

### F2：生命周期事件

Hook 事件必须覆盖以下层级：

- 会话级：会话开始、会话结束、会话清空。
- 轮次级：用户请求开始、模型轮次开始、模型轮次结束、用户请求结束。
- 消息级：用户消息进入、助手消息完成、工具结果消息写入前。
- 工具级：工具执行前、工具执行后。
- 系统级：应用启动后、Hook 配置加载后、运行期错误被捕获后。

事件命名应稳定、可读，并与现有 Agent 概念对齐。工具执行前事件是唯一必须支持拦截的事件；其他事件只执行动作，不改变主流程。

### F3：条件表达式

条件表达式可省略。省略时，事件触发即执行动作。

条件表达式必须复用权限规则的匹配语义：

- 普通标量按精确值匹配。
- 字符串可按 glob 匹配。
- 字符串可按正则匹配。
- 任一匹配可取反。

条件字段以事件上下文中的稳定路径命名，例如工具名、工具参数、消息角色、消息内容、工具结果状态、错误码、轮次编号和会话状态。工具参数中的路径和命令字段应按权限规则相同的规范化方式参与匹配。

逻辑组合只能选择一种：

- `all`：全部谓词满足。
- `any`：任一谓词满足。

同一条规则内不能同时声明 `all` 和 `any`，也不支持嵌套逻辑、表达式求值或任意脚本条件。

### F4：工具执行前拦截

工具执行前 Hook 可以基于工具名和工具参数做细粒度策略判断。命中拦截规则后：

- 真实工具不得执行。
- 系统必须构造结构化工具结果。
- 工具结果必须包含稳定原因码和面向模型的拒绝说明。
- 该工具结果写入对话历史，并随下一轮请求反馈给模型。
- Agent 主流程继续运行，让模型有机会调整方案。

Hook 拦截不能绕过已有权限系统。工具调用仍需经过既有权限检查；Hook 只能在被允许进入执行阶段的调用前进一步收紧行为，不能放宽权限或替代人工审批。

### F5：Shell 命令动作

Shell 命令动作用于执行固定本地命令，例如格式化、测试、生成上下文片段或发送本地通知。

该动作必须支持：

- 命令字符串。
- 可选工作目录。
- 可选环境变量。
- 可选超时时间。
- 可选后台异步执行。

命令超时后记录失败日志，并按 Hook 失败处理，不中断 Agent 主流程。后台命令不向当前模型请求注入输出；前台命令可以把标准输出作为动作结果供后续提示词注入或日志使用。

### F6：提示词注入动作

提示词注入动作用于把固定提示、上下文片段或动作输出加入当前或下一次模型请求。

注入内容必须作为运行期上下文进入请求，不得写入普通对话历史。注入内容应具备明确来源标识，便于测试和排查。工具前拦截场景中，提示词动作可以作为拒绝说明来源，但不得把内部规则细节暴露给模型。

### F7：HTTP 请求动作

HTTP 请求动作用于向本地服务、Webhook 或内部自动化入口发送固定请求。

该动作必须支持：

- URL。
- HTTP 方法。
- 可选请求头。
- 可选 JSON 请求体。
- 可选超时时间。
- 可选后台异步执行。

HTTP 请求失败、超时或响应非成功状态只记录日志，不中断 Agent 主流程。首期不要求把 HTTP 响应内容注入模型。

### F8：子 Agent 动作占位

Hook 配置可以声明启动子 Agent 动作，但本阶段不真实运行子 Agent。命中该动作时，系统只校验配置、记录占位日志，并返回“不支持真实执行”的安全结果。

该占位必须为后续 SubAgent 章节预留必要字段，例如任务描述、输入上下文和期望输出位置，但不得在本阶段启动独立模型调用、后台任务或多 Agent 编排。

### F9：执行控制

每条规则支持以下执行控制：

- `once`：当前进程内只执行一次。
- `background`：后台异步执行。
- `timeout_seconds`：动作超时时间。

`once` 的状态仅保存在当前进程内，本阶段不做跨重启持久化。拦截类事件不允许 `background: true`，否则配置加载失败。未声明超时时间时使用动作类型的安全默认值。

### F10：执行顺序

本阶段不引入显式优先级。多条规则命中同一事件时，按 YAML 中声明顺序执行。

若多条工具前规则都可能拦截同一调用，第一条产生拦截的规则生效，后续规则不再执行该工具调用的拦截动作。其他非拦截事件继续按声明顺序执行，单条失败不影响后续规则。

### F11：失败隔离与日志

Hook 运行期失败包括命令失败、命令超时、HTTP 失败、HTTP 超时、提示词渲染失败、子 Agent 占位执行失败和内部异常。

这些失败必须只记录日志和诊断，不得：

- 中断当前 Agent 请求。
- 阻止模型继续生成。
- 改写已有工具结果。
- 伪装为权限拒绝。
- 泄露环境变量、凭据、完整工具参数或内部堆栈给模型。

配置加载失败不属于运行期 Hook 失败。非法 Hook 配置应在启动或显式加载阶段集中报错，防止系统在不明确规则下运行。

### F12：装配与接入

CLI 启动时加载 Hook 配置并创建 Hook 运行时。Agent Loop 在生命周期节点调用 Hook 入口，工具执行前后传入工具调用、规范化参数、权限后状态和工具结果。

Hook 包负责规则模型、配置解析、条件匹配、动作执行、失败隔离和拦截结果构造。Agent Loop 只负责编排触发点，不复制条件匹配、动作执行或 YAML 校验逻辑。

## 非功能需求

- **N1：架构边界。** Hook 核心实现集中在 `hook` 包，其他包只通过入口对象触发事件。
- **N2：安全保守。** Hook 可以收紧工具执行，但不能放宽权限、跳过审批、扩大路径边界或改变工具读写分类。
- **N3：代码简洁。** 实现保持小模块和直接控制流，不为未来优先级、持久化 once 或真实子 Agent 提前扩展复杂框架。
- **N4：中文注释。** 仅在拦截回填、失败隔离、异步限制和权限复用等关键路径添加简洁中文注释。
- **N5：确定性。** 相同 YAML、事件上下文和进程状态必须产生相同匹配结果、动作顺序和拦截结果。
- **N6：测试隔离。** 自动化测试不得执行真实危险命令、访问真实网络、读取真实凭据或依赖真实用户 Hook 配置。
- **N7：可观测性。** 加载错误、规则命中、动作失败、拦截结果和子 Agent 占位必须有可定位日志。
- **N8：兼容性。** 除新增 Hook 自动化行为外，现有 Agent 事件、工具调度、权限审批、上下文压缩、Skill、斜杠命令和 TUI 行为保持兼容。
- **N9：有界执行。** 前台动作必须受超时控制；后台动作必须通过任务管理避免未观察异常。
- **N10：配置可审计。** YAML 不支持任意表达式、脚本条件、动态导入或从远程地址加载规则。

## 不做的事

- 不实现子 Agent 动作的真实运行。
- 不做 `once` 标记的跨进程或跨重启持久化。
- 不实现 Hook 显式优先级。
- 不实现嵌套条件、任意表达式语言或脚本化条件。
- 不做 Hook 配置热加载或文件监听。
- 不把 Hook 作为权限规则来源，不允许 Hook 创建权限授权。
- 不提供图形化 Hook 编辑器。
- 不把 HTTP 响应自动暴露给模型。
- 不保证后台动作在应用退出后继续运行。
- 不实现分布式任务、重试队列或持久化审计数据库。

## 验收标准

- **AC1（F1）**：合法 YAML 能加载为规则集合；缺少 `event` 或 `action`、未知事件、未知动作、未知字段和非法版本均在加载阶段报错。
- **AC2（F1、F3）**：省略 `if` 的规则无条件触发；声明 `all` 时所有谓词满足才触发；声明 `any` 时任一谓词满足即触发；同时声明两者时报错。
- **AC3（F3）**：条件匹配覆盖精确、反向、正则和 glob；工具参数中的路径和命令字段按权限规则相同方式规范化后匹配。
- **AC4（F2）**：会话级、轮次级、消息级、工具级和系统级事件均可被触发并携带对应上下文。
- **AC5（F4）**：工具执行前 Hook 命中拦截后，fake 工具没有被调用，Agent 产生结构化工具结果，并在下一轮模型请求中可见拒绝原因。
- **AC6（F4、N2）**：被权限系统拒绝或要求审批但未获准的工具调用不会被 Hook 放行；Hook 只能收紧已经允许执行的调用。
- **AC7（F5）**：前台 shell 动作能在临时目录执行固定安全命令并记录输出；命令超时或失败只产生日志，不中断 Agent。
- **AC8（F6）**：提示词注入进入当前或下一次模型请求，不写入普通对话历史，并带有可识别来源。
- **AC9（F7）**：HTTP 动作可向测试用 fake transport 发送方法、URL、头和 JSON；失败或超时只记录日志，不中断 Agent。
- **AC10（F8）**：子 Agent 动作配置可通过校验；命中后不启动模型调用，只记录占位结果。
- **AC11（F9）**：`once` 规则在当前进程内只执行一次；重建 Hook 运行时时可重新执行；不产生持久化状态文件。
- **AC12（F9）**：非拦截事件允许后台异步；工具执行前拦截事件配置 `background: true` 时加载失败。
- **AC13（F10）**：多条命中规则按 YAML 声明顺序执行；工具前第一条拦截规则生效后，不再执行该工具调用后续拦截动作。
- **AC14（F11）**：命令、HTTP、提示词和占位动作抛出异常时，Agent 主流程继续，日志中包含规则 ID 和事件名，不包含凭据或内部堆栈给模型。
- **AC15（F12）**：CLI 启动时加载 Hook 配置并注入 Agent；缺失配置文件等价于空 Hook 配置。
- **AC16（N1、N3、N4）**：代码检查确认 Hook 模型、配置、匹配、执行和接入集中在 `hook` 包；Agent Loop 中只有触发调用；关键路径有简洁中文注释。
- **AC17（N6、N8）**：现有 Agent Loop、工具执行、权限审批、Skill、上下文压缩、斜杠命令和配置测试继续通过。
- **AC18（N6）**：全部 Hook 测试使用临时文件、fake LLM、fake executor 和 fake HTTP transport，不访问真实网络或真实用户配置。
