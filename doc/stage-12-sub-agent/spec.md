# myCode Stage 12：子 Agent 委派与后台任务规格说明

## 背景

myCode 已具备 Agent 循环、工具执行、权限控制、Hook、会话管理、上下文压缩和独立 Skill 执行能力，但主 Agent 仍需在同一对话中承担任务分析、资料读取、验证和结果整理。复杂任务会持续扩大主对话上下文，并混入大量对子任务有用、对主任务无用的中间消息和工具结果。

本阶段引入独立子 Agent。主 Agent 通过一个稳定入口委派任务，子 Agent 在隔离的运行时状态中非交互执行，只把有界结果送回主对话。系统同时支持按预定义角色启动的定义式子 Agent，以及继承父对话前缀的 Fork 式子 Agent。

## 目标

- 提供统一且稳定的子 Agent 委派入口，支持定义式与 Fork 式两种运行方式。
- 通过定义式角色复用固定职责、工具范围、模型档位、最大轮次和权限约束。
- 让 Fork 式子 Agent 继承父对话与工具定义，保持首次请求前缀稳定并利用提示缓存。
- 隔离子 Agent 的消息、权限会话状态、文件读取缓存和 token 用量，同时共享模型访问、Hook、文件系统等基础设施。
- 支持前台等待、显式后台、超时自动转后台和 `Ctrl+B` 手动转后台。
- 将后台结果以有界摘要在安全点回流，详细结果按需查询，避免子任务过程污染主对话。
- 通过多层工具与权限约束阻止越权、后台危险操作和子 Agent 递归委派。
- 在当前会话内追踪任务状态、结果和用量，并支持命令及自然语言查询。

## 功能需求

### F1：统一 Agent 工具

系统只注册一个稳定的 `Agent` 工具，不为角色动态增加工具。该工具支持：

- 运行任务，并通过 `type` 区分 `defined` 与 `fork`
- 查询当前会话的任务列表
- 按任务 ID 查询详情、结果和用量

角色新增、删除、覆盖或任务状态变化不得改变该工具的名称或 schema。

### F2：角色定义格式

每个定义式角色由单个 Markdown 文件表示，文件名必须与角色名一致。YAML frontmatter 必须声明：

- `name`：角色名
- `description`：用途说明
- `allowed_tools`：工具白名单
- `denied_tools`：工具黑名单
- `model`：`inherit / haiku / sonnet / opus`
- `max_rounds`：正整数最大轮次
- `permission_mode`：`inherit / strict / default / permissive`

Markdown 正文是伴随子 Agent 整个生命周期的系统角色提示。

`allowed_tools` 支持具体工具名和 `"*"`；空列表表示不开放普通工具。黑名单优先于白名单。

### F3：角色来源与覆盖

运行时从以下来源加载角色：

```text
项目级 > 用户级 > 内置级 > 插件级
```

项目级使用 `.mycode/agents/<name>.md`，用户级使用 `~/.mycode/agents/<name>.md`。插件级本阶段只保留来源接口和最低优先级定义，不发现或加载实际插件角色。

同名角色只保留最高优先级的有效定义。较高优先级文件无效时，产生可定位诊断并回退到下一有效来源。角色按名称稳定排序。

角色在应用启动时加载；本阶段不要求运行中热更新。

### F4：内置角色

系统提供三个中文内置角色：

- `general`：通用子任务
- `explore`：只读代码与资料探索
- `review`：只读缺陷、风险和测试审查

三个角色均使用统一定义格式，并可被用户级或项目级同名角色覆盖。

### F5：子 Agent 主配置

主配置 YAML 增加子 Agent 配置，至少包含：

- 前台等待超时，默认 120 秒
- 最大后台并发数，默认 4
- `haiku / sonnet / opus` 到当前协议具体模型 ID 的映射
- 后台工具白名单，默认仅允许 `read_file`、`find_files`、`search_code`

角色引用未配置的模型档位时启动失败。所有数值、工具名和模型映射在启动时严格校验。

### F6：定义式执行

定义式子 Agent 从空白对话启动，不继承父消息、父记忆、已激活 Skill 或临时提醒。

它重新获得核心系统规则、工作区环境、项目指令、固定角色正文和本次任务，并按角色配置选择模型、最大轮次、工具范围及权限模式。

定义式任务默认前台等待，也可显式进入后台。

### F7：Fork 式执行

Fork 式子 Agent 在调用时取得父 Agent 的上下文快照，继承父对话历史、系统前缀、模型和完整工具 schema，并在继承前缀之后追加中文 Fork 任务指令。

Fork 不使用定义式角色，不切换模型，最大轮次继承父 Agent 的运行配置，并强制在后台执行。

Fork 的首次请求必须保持父请求的可缓存前缀不变；父 Agent 后续新增消息不得反向进入已经运行的 Fork。

### F8：运行时隔离与基础设施共享

每个子 Agent 独立维护：

- 消息历史
- 权限会话授权与审计记录
- 文件读取缓存
- token 与缓存用量
- 轮次、状态、错误和取消信号

子 Agent 共享模型访问基础设施、Hook 引擎、工作区文件系统、路径安全规则、基础权限策略和工具实现能力。任何子 Agent 的可变运行状态不得写入父 Agent 或其他子 Agent。

### F9：非交互“跑到底”

子 Agent 不向用户发起交互式提问或审批。模型不再调用工具时任务完成；达到最大轮次、发生不可恢复错误或收到取消信号时任务进入对应终态。

单次工具拒绝作为结构化结果回填子 Agent，允许其调整方案继续执行。任务结束时必须形成可供主 Agent 消费的最终结果或稳定错误摘要。

### F10：权限约束

角色权限模式只能继承或收紧父 Agent 的有效权限，严格程度从高到低为 `strict`、`default`、`permissive`；`inherit` 直接采用父 Agent 的有效档位。子 Agent 使用独立的会话授权状态，不继承父 Agent 的临时会话授权。

基础持久策略和系统级安全底线继续生效。非交互执行中仍需人工审批的调用自动拒绝并返回结构化结果；不得暂停后台任务等待用户审批。

### F11：多层工具防线

定义式子 Agent 的有效工具集合依次应用：

1. 全局禁止集
2. 角色白名单
3. 角色黑名单
4. 后台工具白名单
5. 现有权限和路径安全检查

统一 `Agent` 工具始终禁止在任何子 Agent 中实际执行，防止递归委派和无限嵌套。

定义式子 Agent 只看到过滤后的工具 schema。Fork 为保持缓存前缀而持续看到父工具 schema，但每次执行前仍强制应用全局禁止集和后台白名单；被阻止的调用只返回中文结构化拒绝。

前台定义式任务转入后台后，后台白名单作用于后续工具调用，不取消已经开始执行的调用。

### F12：进入后台的方式

系统支持三种后台切换方式：

- 调用时显式指定后台执行
- 前台等待达到主配置中的超时阈值后自动转后台
- 用户在前台运行期间按 `Ctrl+B` 手动转后台

自动或手动切换只解除父 Agent 的等待，不取消、重启或重复执行子 Agent。Fork 始终直接进入后台。

前台任务在转后台前完成时，最终结果直接作为工具结果返回；进入后台时立即返回任务 ID 和当前状态。

### F13：后台调度与状态

后台任务管理器以当前会话为边界追踪任务，状态至少包括：

```text
queued / running / completed / failed / cancelled
```

同时运行的后台任务不超过主配置上限，默认 4 个。超出上限的任务进入 FIFO 队列，并在运行槽位释放后自动启动。

每个任务记录类型、角色、状态、规范化详细结果、错误、轮次和 input/output/total/cache-read/cache-write 用量。

### F14：结果留存与安全点通知

后台任务的最终输出经过大小上限处理后，作为规范化详细结果保存在内存中；超限内容截断并附带明确标记。完成通知只包含有界摘要、任务 ID、终态和用量，不包含完整消息历史或工具调用过程。

通知进入主对话的待处理队列：

- 主 Agent 尚在运行时，在下一次模型调用安全点注入
- 主 Agent 已结束时，在下一次用户请求处理时注入
- 通知不得自行唤醒主 Agent 或触发额外模型请求

### F15：任务查询

用户可通过 `/tasks` 查看当前会话任务列表，通过 `/task <id>` 查看单个任务的状态、规范化详细结果和用量。

当用户用自然语言询问“当前会话任务怎么样”等问题时，主 Agent 必须通过稳定的只读查询能力读取实时任务状态后回答，不依赖陈旧的聊天记录猜测。

本阶段查询能力不提供取消、重跑或恢复操作。

### F16：会话清理

执行 `/clear` 或退出应用时，系统取消所有排队及运行中的子 Agent，等待其安全收尾，并清除任务状态、结果和待注入通知。

后台任务、结果和用量不跨会话或进程持久化。

## 非功能需求

- **N1：领域边界。** 子 Agent 的角色、运行时、工具过滤、后台任务和通知能力集中在独立的 `subAgent` 领域中。现有 Agent、会话、TUI、配置和工具模块只增加必要接入点，不复制第二套 Agent 循环。
- **N2：状态隔离。** 任意两个子 Agent 并发运行时，其消息、权限授权、文件缓存、用量、取消和错误状态不得互相影响，也不得改变父 Agent 的对应状态。
- **N3：缓存兼容。** Fork 首次请求的系统前缀、父历史前缀和工具 schema 必须逐项保持稳定。供应商支持提示缓存且父前缀已缓存时，应能通过 cache-read 用量观察到缓存复用；不支持缓存的协议仍须正确执行。
- **N4：权限单调性。** 角色、后台配置和 Fork 继承只能保持或收紧父权限。项目角色、用户角色、内置角色以及未来插件角色均不能覆盖系统级禁止项或绕过路径安全检查。
- **N5：资源有界。** 角色文件、frontmatter、任务输入、任务结果、通知摘要、排队任务数和已完成任务留存数必须设置明确上限。超限时产生稳定错误，不得无限占用内存。
- **N6：并发安全。** 任务创建、排队、启动、前后台切换、完成、取消和通知入队必须具有确定的状态转换；同一任务只能结算一次并最多发送一次完成通知。
- **N7：确定性。** 相同角色文件、主配置、工具注册表和父上下文必须产生相同的覆盖结果、工具范围、队列顺序、提示构造和状态输出顺序。
- **N8：故障隔离。** 单个角色解析失败、模型失败、工具失败、Hook 失败或子 Agent 取消不得终止其他任务或普通聊天。错误输出不得包含凭据、完整父历史或无关工具结果。
- **N9：可观测性。** 每个任务必须具有稳定 ID，并能观察类型、角色、状态、轮次、结果摘要、错误及 input/output/total/cache-read/cache-write 用量。协议未返回某项用量时明确显示未知，不伪造数值。
- **N10：中文规范。** 系统生成的子 Agent 提示、Fork 指令、内置角色、权限拒绝、任务状态和错误提示全部使用中文。外部角色正文保持原文。所有新增定义类的字段必须带简洁中文注释；复杂隔离、缓存和状态转换逻辑只添加必要的中文说明。
- **N11：兼容性。** 除新增 `Agent` 工具、任务查询命令、`Ctrl+B` 行为和主配置字段外，现有聊天、Skill、权限、Hook、上下文压缩、会话恢复、MCP 和固定斜杠命令行为保持兼容。
- **N12：测试隔离。** 自动化测试使用临时工作区、临时用户目录、fake LLM、fake 工具和确定性调度，不访问真实用户角色、真实网络、真实 API 或工作区外文件。

## 不做的事

- 不做 Worktree、容器或副本级文件隔离。
- 不做并发写入的自动锁定、冲突检测、合并或回滚；显式扩大后台写工具范围时，多个任务仍共享同一工作区。
- 不做多 Agent 团队、角色间通信、共享任务板、依赖图、投票或团队编排。
- 不允许子 Agent 再创建子 Agent。
- 不跨 `/clear`、应用重启或不同会话持久化后台任务、结果、通知或用量。
- 不做后台任务取消、重跑、恢复、优先级调整或手动重排队列入口。
- 不做后台任务完成后自动唤醒主 Agent。
- 不做子 Agent 的交互式权限审批或用户问答。
- 不做角色文件热更新、后台监听或运行中重新加载；修改后需重启应用。
- 不做插件发现、安装、启停或插件角色实际加载，仅保留未来接入接口和优先级位置。
- 不做远程角色市场、下载、签名、版本管理或依赖解析。
- 不做目录型角色、附属资源、模板或辅助脚本。
- 不改变现有 Skill 的定义格式和执行语义。
- 不保证所有供应商都提供提示缓存或完整用量字段，只保证请求前缀兼容与未知值正确表达。
- 不提供图形化任务面板；本阶段仅提供 TUI 状态反馈、快捷键、斜杠命令和自然语言查询。

## 验收标准

- **AC1（F1）**：模型只看到一个 `Agent` 工具，并能通过固定参数分别启动定义式与 Fork 式任务。
- **AC2（F1、F15）**：新增、删除、覆盖角色及任务状态变化前后，`Agent` 工具 schema 完全一致；列表和详情查询均通过其只读能力完成。
- **AC3（F2）**：合法单文件角色可加载；文件名不匹配、缺少字段、正文为空、非法模型档位、非正数最大轮次或非法权限模式均产生可定位诊断。
- **AC4（F2、F11）**：`allowed_tools: ["*"]` 表示全部候选工具，空列表不开放普通工具；白名单与黑名单冲突时工具不可用。
- **AC5（F3）**：项目、用户和内置来源存在同名角色时项目版本生效；高优先级版本无效时回退到下一有效版本并产生诊断。
- **AC6（F3）**：插件来源接口和最低优先级存在，但未配置插件系统时不扫描或加载任何插件角色；运行中修改角色文件不会隐式热更新。
- **AC7（F4）**：默认安装可发现 `general`、`explore`、`review` 三个中文角色，用户级或项目级同名文件可覆盖它们。
- **AC8（F5）**：省略可选子 Agent 配置时使用 120 秒前台超时、4 个后台并发和三个默认只读工具；非法数值、未知工具或缺失模型映射使启动失败。
- **AC9（F6）**：定义式子 Agent 的首个请求包含核心规则、工作区环境、项目指令、角色正文和任务，但不包含父消息、父记忆、父 Skill 或父临时提醒。
- **AC10（F6）**：定义式角色选择逻辑模型档位后，请求只替换具体模型 ID 并复用当前协议配置；达到角色最大轮次后以稳定状态结束。
- **AC11（F7、N3）**：Fork 首次请求的父系统前缀、历史前缀和工具 schema 与父请求逐项相同；fake usage 可观察 cache-read，未提供缓存用量时显示未知。
- **AC12（F7）**：Fork 始终返回后台任务 ID，使用父模型和父最大轮次；创建后的父消息不会进入 Fork 快照。
- **AC13（F8）**：两个并发子 Agent 使用不同消息、权限授权、文件缓存和用量对象；任一方修改状态后另一方及父 Agent 保持不变。
- **AC14（F8）**：子 Agent 可访问同一工作区并触发现有 Hook；Hook 或文件系统实例共享不会导致子 Agent 状态串扰。
- **AC15（F9）**：fake LLM 在若干工具轮后停止调用工具时任务完成；最大轮次、取消和不可恢复错误分别进入确定终态。
- **AC16（F10）**：角色声明更宽松权限时有效权限不超过父 Agent；子 Agent 不复用父临时授权，遇到 `ASK` 时工具不执行并收到结构化拒绝。
- **AC17（F11）**：定义式子 Agent 请求中只出现多层过滤后的工具；转后台后，后续调用进一步受后台白名单限制。
- **AC18（F11）**：Fork 持续看到父工具 schema，但后台禁用工具和 `Agent` 工具在执行前被拒绝，executor 调用数保持为零。
- **AC19（F12）**：显式后台、等待 120 秒自动后台和运行中按 `Ctrl+B` 均使父 Agent 获得任务 ID，子 Agent 继续且只执行一次。
- **AC20（F12）**：前台任务在阈值前完成时直接返回最终结果；切换后台时已开始的调用不中断，后续调用应用后台限制。
- **AC21（F13）**：并发上限为 4 时，第 5 个任务进入 `queued`；任一运行任务结束后，最早排队任务首先启动。
- **AC22（F13、N9）**：任务详情展示类型、角色、状态、轮次、结果、错误及五类 token/cache 用量；缺失字段明确显示未知。
- **AC23（F14）**：后台完成不会自动调用模型；通知只在下一模型安全点或下一用户请求注入，并且每个任务最多注入一次。
- **AC24（F14、N5）**：通知只包含有界摘要。超长最终输出按上限截断并带明确标记，任务详情返回任务管理器保存的规范化详细结果。
- **AC25（F15）**：`/tasks`、`/task <id>` 和“当前会话任务怎么样”均读取实时状态；不存在的任务 ID 返回中文稳定错误。
- **AC26（F16）**：执行 `/clear` 或退出时，排队及运行任务全部取消并安全收尾，结果和通知被清空，重启后不可恢复。
- **AC27（N6-N8）**：并发完成、超时切换与取消竞争时，每个任务只有一个终态和一次通知；单任务失败不影响普通聊天或其他任务。
- **AC28（N10-N12）**：系统子 Agent 提示、内置角色和用户提示均为中文；新增定义类字段具有中文注释；完整测试不访问真实网络、API、用户角色或工作区外文件，现有回归测试通过。
