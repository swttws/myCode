# myCode Stage 13：子 Agent Worktree 隔离规格说明

## 背景

myCode 已支持定义式与 Fork 式子 Agent 并行运行，并隔离各自的消息、权限、文件缓存和用量状态，但它们仍共享主 Agent 的工作目录。只要后台工具范围允许写操作，多个 Agent 就可能覆盖彼此文件、读取到执行期间出现的中间状态，或被主 Agent 的未提交修改干扰。

本阶段引入基于 Git 多工作目录机制的文件级隔离。需要隔离的定义式子 Agent 在独立分支和独立工作目录中运行，同时与主仓库共享版本库对象。隔离目录位于仓库内已忽略的位置，不进入版本控制。

## 目标

- 为声明 Worktree 隔离的定义式子 Agent 自动建立独立、可识别且可恢复的工作目录。
- 用集中式生命周期管理统一处理安全命名、创建、快速恢复、环境初始化、进入、退出、删除和过期清理。
- 所有工具和路径相关上下文显式使用目标工作目录；不修改进程级当前目录。
- 让文件缓存、系统提示词、项目指令和项目记忆天然按规范化绝对路径隔离。
- 在任务结束或后台清理时保护未提交修改和未推送提交，只有通过安全检查的临时目录才可自动删除。
- 保持主 Agent、Fork 子 Agent 和未声明隔离的定义式子 Agent 现有行为不变。

## 功能需求

- **F1：角色声明。** 定义式角色可在 frontmatter 中声明 `isolation: worktree`。未声明时保持共享工作区；Fork 不支持该字段，也不创建 Worktree。未知隔离值产生可定位诊断。
- **F2：目录与分支。** 隔离目录固定组织为 `.worktrees/<角色名>/<任务标识>`，临时分支使用对应的受控前缀。创建基线是任务启动时主仓库已提交的 `HEAD`，不复制主工作区未提交修改。
- **F3：名称安全。** 相对名称只能由 `/` 分隔的 ASCII 安全段组成；每段 1–64 字符、整体不超过 200 字符，段首尾必须是字母或数字，中间只允许字母、数字、点、下划线和连字符。空段、`.`、`..`、绝对路径、反斜杠、盘符、控制字符和平台保留名称全部拒绝。
- **F4：目录边界。** 应用启动时确认 `.worktrees/` 位于仓库内且已被 Git 忽略；后续创建、恢复和删除复用该校验结果，并在每次操作前重新确认目标的规范化真实路径仍位于该根目录下。边界无法确认时拒绝操作，不自动修改忽略规则。
- **F5：首次创建。** 目标不存在时，通过 Git 创建独立分支和 Worktree；目录冲突、分支冲突、Git 不可用或当前目录不是有效仓库时，子 Agent 不启动并返回稳定错误。
- **F6：快速恢复。** 目标已存在时不得调用 Git，也不得执行任何写操作。系统只读取管理区元数据和目录结构，确认仓库身份、任务身份、规范化路径、分支及初始化完成状态全部匹配后复用；缺失、未完成或不匹配时拒绝恢复。
- **F7：初始化配置。** 环境初始化规则由项目级配置显式声明，并在应用启动时严格校验。非法路径、重复目标、越界来源、循环链接或未知规则类型使配置失败，不推迟到子 Agent 运行期间处理。
- **F8：初始化动作。** 首次创建后按配置顺序执行：复制本地配置、为子工作目录设置独立 Git hooks、为大型依赖目录创建符号链接，以及补齐明确列出的被忽略运行文件。所有来源和目标都必须经过路径边界检查，且不得改变主工作区的有效 hooks 配置。
- **F9：初始化失败。** 任一必需步骤失败时不启动子 Agent。本次新建的 Worktree 仅在确认没有受保护变更后回滚，并返回失败步骤和安全诊断；快速恢复验证失败的既有目录始终保留。日志与错误不得泄露复制文件的内容或凭据。
- **F10：进入工作区。** 进入隔离模式只生成并传递包含规范化绝对目录、分支和任务身份的工作区上下文，不调用 `chdir`，也不修改进程级当前目录。
- **F11：显式路径传递。** 每次工具调用的调度上下文都显式携带目标工作目录。文件工具、命令工具、权限边界、Hook、Skill、上下文归档及其他路径相关操作必须使用该上下文；未接收工作区上下文的组件不得退回主目录执行。
- **F12：上下文隔离。** 文件内容、系统提示词、项目指令和项目级记忆的读取、缓存与存储身份均使用规范化绝对工作区路径。相同相对路径位于不同 Worktree 时必须形成不同条目，无需在进入或退出时清空全局缓存。
- **F13：路径提示。** 子 Agent 启动时获得当前 Worktree 绝对路径、临时分支和隔离约束说明；项目指令从该 Worktree 重新加载。提示明确要求所有文件操作只针对隔离目录。
- **F14：退出与变更保护。** 子 Agent 进入成功、失败或取消终态后释放运行资源并检查工作区。暂存修改、未暂存修改和非忽略的未跟踪文件均视为未提交修改；任何未被 upstream 包含的新增提交视为未推送提交。无 upstream 时，相对创建基线产生的提交视为未推送。
- **F15：自动处置。** 工作区无未提交修改且无未推送提交时，自动删除 Worktree 及对应临时分支；否则保留，并向主 Agent 报告绝对路径、分支和保护原因。当前阶段不提供绕过保护的强制删除入口。
- **F16：后台清理。** 系统启动后执行一次受控临时目录扫描，之后默认每 1 小时扫描一次；扫描间隔和默认 7 天的过期时间均可由项目配置调整。删除必须依次通过三层过滤：受控身份与真实路径有效、目录已过期且没有活动任务、工作区不存在受保护变更。任一层失败即跳过并记录有界诊断。
- **F17：并发一致性。** 同一任务身份或目标路径的创建、恢复、退出和清理必须串行化；并发请求只能产生一个有效所有者，不得重复创建、重复删除或把正在运行的目录判为过期。
- **F18：可观测性。** 现有任务状态和详情应展示隔离模式、工作目录、临时分支、首次创建或快速恢复状态、初始化结果，以及最终删除或保留原因；本阶段不新增手动 Worktree 命令。

## 非功能需求

- **N1：领域边界。** Worktree 的身份、生命周期、初始化、变更检测和清理集中在独立领域中。子 Agent、工具、Hook、Prompt、Memory 和 Skill 只通过工作区上下文接入，不各自实现 Git 生命周期逻辑。
- **N2：失败关闭。** 路径、仓库身份、元数据、Git 状态或变更保护只要无法可靠判断，就必须拒绝创建、恢复或删除，不得按“可能安全”继续。
- **N3：路径安全。** 所有边界检查基于规范化绝对真实路径，并防御符号链接、目录联接、重解析点、大小写差异和检查后替换。用户或模型提供的文本不得直接拼接成未经校验的文件路径或 Git 引用。
- **N4：命令安全。** Git 操作使用结构化参数和显式工作目录执行，不通过可注入的 shell 字符串拼接。每次调用都有退出码检查和有界输出，默认超时为 30 秒，并允许项目在 1–120 秒范围内调整。
- **N5：进程安全。** 系统在任何并发路径中都不得调用 `chdir`。主 Agent 与多个子 Agent 同时运行时，任一任务的当前工作目录、路径权限或缓存身份不得影响其他任务。
- **N6：一致性与恢复。** 创建、初始化、状态落盘和清理具有明确阶段。中断后只能恢复已完整初始化且身份匹配的目录；半成品保持可识别，不得被误当成可运行环境。
- **N7：确定性。** 相同仓库、角色、任务身份、基线和项目配置必须产生相同的目录、分支、初始化顺序、保护判断和诊断顺序。
- **N8：资源有界。** 初始化规则最多 128 条，单条规则中的来源或目标路径文本最多 512 字符，单份元数据最多 64 KiB，单批最多扫描 64 个目录，单次 Git 标准输出和标准错误分别最多保留 64 KiB，单条诊断最多保留 4 KiB。后台清理分批执行，不阻塞普通聊天或正在运行的子 Agent。
- **N9：快速恢复性能。** 合法既有目录的恢复只进行有界只读文件检查，不启动 Git 进程、不重新初始化环境，也不遍历整个仓库。
- **N10：平台行为。** Windows、Linux 和 macOS 使用一致的安全语义。平台不允许创建所声明的符号链接时初始化明确失败，不静默改为复制大型依赖目录。
- **N11：兼容性。** 未声明隔离的角色、Fork、普通聊天、权限、Hook、Skill、上下文压缩、会话恢复、MCP 和现有工具 schema 保持兼容。Worktree 隔离不得改变主工作区文件或 Git 配置。
- **N12：隐私与可观测性。** 日志记录任务身份、阶段、路径、分支、Git 退出状态和保护原因，但不记录本地配置内容、环境变量值、凭据或完整 Git 输出。
- **N13：测试隔离。** 自动化测试使用临时 Git 仓库、临时用户目录、受控文件和 fake 调度，不访问真实远端、不推送真实分支、不读取真实用户配置，也不依赖测试进程的当前目录切换。
- **N14：中文规范。** 系统生成的隔离提示、错误、保护原因和清理诊断使用中文；新增数据字段具有简洁中文说明，复杂安全判断只保留必要注释。

## 不做的事

- 不做 Worktree 分支之间的自动合并、变基、拣选、冲突解决或合并策略选择；由上层显式使用 Git 决定。
- 不把主工作区未提交修改复制、暂存或同步到子 Worktree。
- 不在多个 Worktree 之间实时同步文件、缓存、构建产物或代码变更。
- 不做多 Agent 依赖图、团队调度、任务分配、共享任务板或 Agent 间通信。
- 不为 Fork 子 Agent 创建 Worktree，也不改变未声明隔离的定义式角色。
- 不新增 Worktree 管理命令、图形界面或供用户手动强制删除的入口。
- 不使用容器、完整仓库副本、进程级 `chdir` 或文件写入锁代替 Git Worktree。
- 不自动提交、推送、创建远端分支或修改 upstream；系统只检测这些状态并保护变更。
- 不提供绕过未提交修改或未推送提交保护的自动强制清理。
- 不自动推断需要复制或链接的本地文件；环境初始化仅执行项目显式声明的规则。
- 不负责安装依赖、更新 Git submodule、下载 Git LFS 对象或修复项目自身的环境问题。
- 不跨不同 Git 仓库共享 Worktree，也不允许初始化规则访问配置范围外的任意绝对路径。
- 不因工作区切换主动清空所有缓存；隔离依赖绝对路径身份。
- 不改变现有子 Agent 任务的会话级状态留存策略，Worktree 元数据只服务于目录身份验证和安全清理。

## 验收标准

- **AC1（F1）**：声明 `isolation: worktree` 的定义式角色使用隔离目录；未声明的角色和 Fork 继续使用原工作区。非法值产生诊断且角色不能启动。
- **AC2（F2–F3）**：同一角色的两个任务得到不同的受控目录和临时分支，名称符合长度与字符规则。
- **AC3（F3–F4）**：包含空段、`.`、`..`、绝对路径、反斜杠、盘符、平台保留名或超长段的名称全部被拒绝，仓库外文件保持不变。
- **AC4（F4）**：将 `.worktrees/` 替换为指向仓库外的链接或目录联接后，创建、恢复和清理均拒绝执行。
- **AC5（F2、F5）**：主工作区有未提交修改时创建隔离任务，子 Worktree 基于启动时已提交 `HEAD`，看不到这些未提交修改。
- **AC6（F5）**：首次创建后，Git 可观察到独立工作目录和独立临时分支；主工作区分支、索引和文件内容不变。
- **AC7（F6、N9）**：目标目录和完整元数据已存在时可快速恢复；记录器确认全过程没有 Git 调用、文件写入或仓库遍历。
- **AC8（F6）**：元数据缺失、初始化未完成、仓库身份不符、任务身份不符或路径不符时，恢复失败且既有目录不被修改。
- **AC9（F7）**：合法项目初始化配置可加载；未知规则、重复目标、越界路径、循环链接或超限配置在启动时产生稳定错误。
- **AC10（F8）**：配置声明的本地文件被复制、依赖目录被链接、忽略文件被补齐，并且子 Worktree 使用自己的 hooks 设置，主工作区 hooks 行为不变。
- **AC11（F9）**：首次创建后的必需初始化步骤失败时，子 Agent 不启动且安全回滚；快速恢复验证失败时既有目录不会被删除或改写。
- **AC12（F10–F11）**：并发运行主 Agent 和两个隔离子 Agent 时，进程当前目录始终不变；每个工具、Hook 和 Skill 只观察到显式传入的工作目录。
- **AC13（F12）**：两个 Worktree 中相同相对路径的文件内容、Prompt、项目指令和项目记忆使用不同绝对身份；一方更新不改变另一方缓存结果。
- **AC14（F13）**：隔离子 Agent 的首个请求包含正确的绝对路径、临时分支和隔离说明，并加载该 Worktree 内的项目指令。
- **AC15（F14–F15）**：成功、失败和取消任务在工作区干净且没有未推送提交时均自动删除 Worktree 和临时分支。
- **AC16（F14–F15）**：存在暂存、未暂存或非忽略未跟踪文件时退出拒绝删除，并报告目录、分支及未提交修改原因。
- **AC17（F14–F15）**：存在 upstream 未包含的提交时退出拒绝删除；新分支无 upstream 且相对基线有新增提交时同样视为未推送。
- **AC18（F14–F15）**：新增提交已被 upstream 包含且工作区干净时允许自动删除，不要求自动合并或推送。
- **AC19（F16）**：启动时执行一次清理扫描，fake 时钟推进 1 小时后执行下一次；默认以 7 天为过期线，调整项目配置后采用新的扫描间隔和过期时间，未过期目录不会被删除。
- **AC20（F16）**：伪造元数据、越界链接、活动任务、未提交修改或未推送提交分别使后台清理在对应过滤层停止。
- **AC21（F16、N8）**：存在超过 64 个临时目录时，首批只处理 64 个并在后续批次继续；普通聊天和活动子 Agent 仍可继续运行。
- **AC22（F17）**：并发创建、恢复、退出和清理同一路径时只产生一个有效所有者、一个终态和至多一次删除。
- **AC23（F18）**：任务列表和详情可观察隔离模式、绝对路径、临时分支、创建或恢复、初始化结果及删除或保留原因。
- **AC24（N2–N4、N12）**：路径或 Git 状态无法确认时操作失败关闭；错误与日志不包含配置正文、环境变量值、凭据或无界 Git 输出。
- **AC25（N10、N13）**：临时仓库测试覆盖 Windows、Linux 和 macOS 路径语义；不访问真实远端、真实用户配置或工作区外文件。
- **AC26（N11）**：现有聊天、定义式共享角色、Fork、权限、Hook、Skill、Memory、MCP、上下文管理和子 Agent 回归测试全部通过。
- **AC27（端到端）**：主 Agent 启动一个隔离角色，系统创建并初始化 Worktree，子 Agent 在其中修改并提交文件；主工作区不受影响，任务结束后因提交未推送而保留目录并报告保护原因。
- **AC28（端到端）**：再次运行一个未产生变更的隔离任务，系统完成运行后自动删除其 Worktree 和临时分支，不影响前一个受保护目录。
