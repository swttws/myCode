# 文件搜索工具增强修复记录

## 问题

`find_files` 只支持 glob 和有限的文件名精确匹配，`search_code` 只支持区分原文的字面量匹配。用户使用错别字、大小写差异、中文/英文常见同义词，或省略搜索目录时，容易得到空结果。

## 根因

- 文件名工具只调用 glob/扩展名省略逻辑，没有归一化和候选排序。
- 内容工具只判断 `query in line`，没有对查询和候选文本做统一规范化。
- `root` 虽然代码默认使用工作区根目录，但工具描述没有明确说明“省略或留空会递归搜索整个工作区”，模型容易把文件名查询误用成内容查询或反复指定错误目录。

## 修复内容

- `find_files` 保留 glob 和精确匹配，并在无精确结果时支持路径/文件名的大小写、Unicode、分隔符、CamelCase 归一化、错别字相似度和内置中英文别名。
- `search_code` 保留字面量结果优先，在无字面量结果时对文本行使用同一套归一化、错别字和别名匹配。
- `root` 缺省、`null` 或空字符串统一回退到工作区根目录；显式目录仍通过 `PathGuard` 校验。
- 工具描述、参数描述和 README 已说明新的搜索行为。

## 验证

- `pytest -q tests/test_tool_filesystem.py tests/test_tool_registry.py`：50 passed。
- 新增回归覆盖：文件名错别字、文件名中文同义词、内容错别字、内容中文同义词、缺省目录和空目录。
